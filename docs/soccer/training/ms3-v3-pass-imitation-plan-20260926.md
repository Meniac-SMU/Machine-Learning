# MS3-v3 패스 모방학습 → PPO 재개 계획

작성일: 2026-09-26. 상태: **계획 수립 완료 / 구현·데이터 수집·학습 미착수**.

사용자가 승인한 방향은 현재2M 모델의 능력을 보존하면서, 패스에 유리한 상황의 짧은 모방학습으로 자율적인 패스 선택을 늘리고 PPO로 이어가는 것이다. 이번 요청의 실행 범위는 계획 문서 작성까지다. 아래 구현·수집·학습·검증은 이후 수행할 작업이며 지금 완료된 것으로 해석하지 않는다.

## 1. 목표와 변경 경계

목표는 패스 횟수 자체를 채우는 것이 아니라, **운반이 불리하고 유효한 수신 경로가 있는 상황에서 감독이 PassBuild를 선택하고 실제 타격·의도된 수신으로 연결하는 능력**을 만드는 것이다. 패스가 불필요한 상황의 운반·슛·수비 능력도 유지한다.

유지할 계약:

- Behavior `MNG_ManagerV2`, 관측244, 단일 이산 행동6개, 기존 관측·행동 의미.
- 기존 선수 이동·드리블·패스 준비/타격/수신, 공통 걷어내기, 물리·경기 규칙과300초 경기.
- 기존 보상·상한, PPO 하이퍼파라미터와 네트워크 구조. 첫 실험에서 beta·패스 보상·행동 허용 조건을 동시에 바꾸지 않는다.
- 실행·평가 시 모델의 실제 출력을 사용한다. 강제 패스, 행동 덮어쓰기, 패스 횟수 할당량, 패스 확률 하한, 전술적 행동 마스크 추가를 사용하지 않는다. 기존 합법성 마스크는 유지한다.
- 현재2M champion과 원본 Run·모델·optimizer·상대 풀·로그는 보존한다. 새 미세조정 후보는 별도 Run/증거 폴더에서 관리하고 MS3-v3 명칭을 유지한다.

시범 수집의 교사 정책은 데이터 제작용이다. 학습 모델의 실제 판단으로 가장하지 않으며, 교사 행동을 PPO의 on-policy 경험 버퍼에 섞지 않는다. 교사 개입·자율 정책·공통 선수 기술을 출처별로 구분한다.

|확인 사항|계획에 반영할 조치|

## 5. 시범 데이터의 정의

### 5.1 좋은 패스 후보

다음 조건을 만족하는 상황에서 교사가 현재6개 명령 중 PassBuild를 선택하는 사례를 만든다.

- 실제 활동 상태이며 제어 가능한 AI 선수가 공을 소유한다. 기존 마스크에서 PassBuild가 허용된다.
- 전진 운반이 막히거나 압박 때문에 불리하다는 관측 가능한 근거가 있다.
- 기존 target resolver가 정한 유효한 동료와 열린 경로가 있다. 기존 거리·전방·슛 구역 제한을 임의로 완화하지 않는다.
- 단순히 패스가 가능하다는 이유만으로 정답 처리하지 않는다. 운반/슛이 명백히 유리한 상황을 구분한다.
- 결과는 기존 물리와 선수 실행 경로로 얻는다. 타격·의도된 수신·그 뒤 소유 유지 또는 전진을 확인한다. 판정 시간창·압박/이점 기준은 구현 전 확정한다.

교사는 현재 관측244개와 합법성 마스크에서 얻을 수 있는 정보만으로 행동을 결정하는 것을 원칙으로 한다. runtime의 추가 필드로 라벨을 만들 경우, 그 판단 정보가 학습 입력에도 표현되는지 먼저 점검한다. 미래 수신/득실점 정보는 결과 검증·정제에만 사용하고 정책 입력에는 넣지 않는다.

### 5.2 비패스 유지 데이터

- 전진 경로가 열린 운반, 슛이 유리한 상황, 공을 소유하지 않은 회수·수비, 패스 경로가 막히거나 불리한 상황을 포함한다.
- **패스가 합법이지만 선택할 필요가 없는 상황**도 포함한다. 불법 패스 상태만 음성 사례로 쓰면 적절한 선택을 배우기 어렵다.
- 동결2M의 관측별 유효 행동 확률을 보존한다. 권장안은 비패스 유지 구간에서 원래 분포에 대한 KL 손실로 기존 행동을 유지하는 것이다. 이것은 모든 상황에2M 출력을 강요하는 규칙이 아니다.
- 적극적으로 패스를 가르치는 상태에2M의 거의0인 패스 확률을 강하게 동시에 맞추지 않는다. 학습 목적이 충돌하지 않도록 데이터 역할을 분리한다.
- 불확실한 교사 판단은 정답으로 확정하지 않고 보류한다. 좋은 패스 학습 데이터의 혼합비는 실제 경기에서의 패스 할당량과 다르다.

### 5.3 저장·정제·분할

각 표본은 observation244, validMask6, teacherAction, 부모2M 확률분포, team, seed, match/episode/tick, 판단 사유, runtime/교사 버전, parentCommandId/taskId/kickId, 타격·취소·수신·소유 변화·득실점 결과를 연결한다. 없는 연결 필드는 누락을 표시하고 결과를 추정해 채우지 않는다.

한 패스 기회에서 연속된 유사 프레임을 과도하게 반복 수록하지 않는다. 실제로 선택한 관측 시점과 실행 후 관측을 혼동하지 않으며 실행하지 않은 행동을 실행했다고 재라벨링하지 않는다. 출력 보존용 soft-label과 실제 교사 실행 사례를 구분한다.

모든 시도와 실패·취소·인터셉트·보류 사유를 원본에 남긴다. 성공 사례만 정제하더라도 교사의 전체 성공률과 실패 상황을 함께 보고한다. 성공한 우연한 seed만으로 일반적 안전성을 주장하지 않는다.

학습/검증/최종 보류 집합은 **경기·episode·seed 단위**로 나누고 양 진영 쌍도 같은 집합에 둔다. 인접 프레임을 서로 다른 집합에 나누지 않는다. 다양한 상대·구역·진영·압박 상태를 포함하고 출처별 분포를 보고한다. 최종 보류 집합과 champion 대결용 새 seed는 학습·교사 튜닝에 사용하지 않는다.

## 6. BC와 PPO 연결 설계

### 6.1 권장 학습 목적

개념적인 목적은 다음과 같다. 가중치·epoch·학습률·상한은 아직 실행값이 아니다.

`L = 패스 시범의 masked CE + 보존 상태의 KL(동결2M || 후보)`

두 항은 각각 해당 데이터 구간에 적용한다. 손실은 구간별로 정규화하여 비패스 표본 수가 패스 학습을 모두 압도하지 않게 한다. 기존 합법성 마스크를 적용하고 teacherAction이 허용된 행동인지 검증한다. softmax와 log-prob 계산에서 masked 항의 NaN/무한값을 방지한다.

첫 BC는 actor만 수정하는 것을 권장한다. critic 가중치는 보존하며, 실제 actor/critic이 파라미터를 공유하는지 먼저 검사한다. BC update 수·처리 표본 수·데이터 epoch는 환경 학습 step과 별도로 센다. BC가2M의 환경 경험을 새로 쌓았다고 기록하지 않는다.

모방 영향 감소는 BC 단계에서 독립 카운터로 관리하고, PPO 본 학습 시작 시 BC 손실을0으로 하는 명시적 전환을 기본안으로 한다. 짧은 PPO+BC 혼합 전환이 필요하면 별도 길이·강도를 정해 승인된 범위 안에서만 추가한다. 기본 설정에 의해 무기한 모방이 계속되게 하지 않는다.

### 6.2 optimizer·pool·카운터

|대상|권장안|확인할 위험|
|---|---|---|
|부모 원본|2M 전체 저장본 보존, 새 후보는 별도 위치|ONNX만으로 optimizer·critic·pool을 복원했다고 주장하지 않음|
|BC optimizer|새 BC용 optimizer, 상태·난수·카운터 모두 저장|중단 재개 때 Adam·데이터 순서가 초기화되는 문제|
|PPO optimizer|BC로 actor를 바꾼 뒤 PPO momentum은 새로 시작하는 안을 권장. critic 가중치는 이어받음|기존 PPO optimizer 유지와는 다른 실험. 최종 선택은 구현 전 확정. 원래 optimizer를 폐기하지 않음|
|상대 풀|2M pool의 유효 snapshot·원래MS2 pinned·구성 원칙을 분기 복사해 이어받는 안을 권장|새 pool 초기화를 몰래 수행하지 않음. BC 결과가 과거 deployed 정책으로 덮이지 않는지 확인|
|학습 정책 배포|분기 상태를 복원한 뒤 BC actor를 학습 정책과 관련 queue에 정확히 동기화|opponent snapshot·current/latest snapshot·learning actor를 혼동하지 않음|
|경험 버퍼|BC 이전 rollout은 재사용하지 않고 새 actor로 다시 수집|교사 시범을 PPO rollout으로 취급하지 않음|
|step|부모 환경 step2,001,834, 추가 PPO 전이, BC update를 각각 기록|poolStep와trainerStep 일치, nominal milestone과 실제 batch 초과분 구분|

별도 Run이라고 학습 경험 전체가0인 모델로 표기하지 않는다. original MS2 ancestry, immediateParent2M, BC dataset hash, BC output hash, PPO fork 방식을 모두 남긴다. 기존 v2 r005·격리 r001/r900 자격 제한은 유지한다.

## 7. 검증과 평가

### 7.1 개발·데이터 검증

- 부모 로드 직후, 업데이트 전 동일 관측·마스크의 확률분포가2M과 일치한다.
- observation/action schema·finite·teacherAction 합법성·관측 시점 정렬·데이터 집합 분리·출처 연결을 확인한다.
- BC 중 의도한 actor만 변경되는지, 저장/복원 시 optimizer·난수·카운터가 이어지는지 검증한다.
- 오프라인 검증에서 좋은 패스 상태의 확률/분류, 합법이지만 불필요한 패스 상태의 오선택, 비패스 구간의 분포 변화와6개 행동을 함께 확인한다.
- ONNX 확률 추론과 학습 actor의 확률,32환경의 학습팀/상대 배포, pool 계보를 점검한다.
- 필요 시 작은 실행 연결 점검으로 관측→명령→타격/취소→수신 기록을 확인한다. 이 진단은 정규300초 평가 경기나 champion 성적에 섞지 않는다.

BC 학습 loss 감소만으로 경기 품질을 통과 처리하지 않는다. 패스 데이터 밖 행동이 무너지거나 teacherAction 정렬·마스크·checkpoint 복원에 문제가 있으면 해당 단계를 중단한다. 숫자 기준은8절에서 확정한다.

### 7.2 학습 점검·상세평가 주기

- PPO는 기존32환경을 유지한다.100k 단위에는 저장·오류·메모리·loss/KL/entropy·학습팀 노출·행동 로그를 점검하며 평가 경기를 하지 않는다.
- 정규 평가 경기는400k 간격을 유지한다. **첫 구간은 명목2.4M까지를 제안**하지만, 추가 학습 상한은 아직 승인·확정되지 않았다. 실제 저장 step과 실제 추가 전이를 별도 기록한다.
- 현 champion과 직접 대결:300초·양 진영 쌍·기본40경기, 승률 차이5%p 이하이면20경기 추가, 이후 완전 동률만40경기씩 추가한다. 새 후보가 누적 승수로 앞서면 교체한다.
- MS2·Full·Recover·carry-shot·Balanced·유효한 과거 정책을 대상으로 기존 지표 평가를 유지한다. 무작위 상대는 제외한다. 동일 상대·seed·진영 비교와 독립 champion seed를 구분하고, 동일 상대 중복은 명시적으로 정리한다.
- 다양한 상대의 경기력·패스 개선 여부·신뢰구간은 별도 지표다. 이를 사용자가 정한 champion 교체의 추가 문턱으로 삼지 않는다. 따라서 패스 목표 달성과 champion 승격은 별도로 보고할 수 있다.

### 7.3 패스 품질 지표

분모를 분리하여 기록한다.

|구간|지표|
|---|---|
|기회|활동·소유 상태의 결정 수, 패스 허용 수, 그중 운반 불리/패스 이점 상태 수|
|선택|허용 상태의 PassBuild 확률·선택률, 패스가 합법이지만 불필요한 상태의 선택률|
|실행|PassBuild 선택→준비→실제 타격 전환율, 취소 사유별 비율, 의도된 수신/인터셉트|
|결과|패스 후 소유 유지/상실·전진·슛/득실점과 시간창; 단순 상관을 인과효과로 부르지 않음|
|일반 성능|승·무·패, 승률/승점률, 득실점, 진영별 성적, 수비 위험·정체|
|유지|BC 직후 오프라인 변화, BC 종료 후 PPO 로그 및400k 평가에서 능력 유지 여부|

감독 PassBuild와 공통 선수 기술에서 나온 패스를 분리한다. raw/rewarded/capped 이벤트도 분리하며 성공 패스 보상 건수를 감독 패스 학습의 직접 증거로 사용하지 않는다.

2M 동결 비교만으로 BC의 순수 효과를 분리할 수는 없다. 인과효과를 분리하려면 동일 부모·동일 PPO 예산의 **BC 없는 PPO 대조 실험**이 필요하다. 이는 별도 비용이므로 기본 실행 범위에 자동 추가하지 않는다. 대조 실험을 하지 않으면 결과를 BC+PPO 전체 변경의 결과로 한정한다.

## 8. 착수 전에 확정할 결정

아래 항목은 계획의 미해결 결정이며 임의의 실행값으로 채우지 않는다. 데이터 관찰로 정할 값과 사용자가 선택할 범위를 구분한다.

|결정|권장 방향|확정 시점|
|---|---|---|
|교사 정의|현재 관측에 근거한 조건부 교사 + 실제 실행 결과 검증.2M 비패스 분포로 보존 사례 구성|수집 구현 전|
|운반 불리/패스 이점·성공 후 관찰 시간창|기존 판정 재사용을 우선하고 새 숫자가 필요하면 명시적으로 결정|수집 전|
|표본량·혼합비·검증/보류 비율|기회 단위 중복과 상황별 커버리지를 확인한 뒤 숫자 확정. 패스 횟수 할당량으로 전용하지 않음|파일럿 수집 설계 확정 시|
|BC 학습률·손실 비중·update/epoch 상한·조기 종료 허용치|작은 변경부터 검증, 고정된 유한 상한과 비패스 보존 허용치 설정|BC 실행 전|
|critic·PPO optimizer 처리|critic 가중치 보존 + PPO optimizer 새 시작 권장. 원본 optimizer는 보존|전환 구현 전|
|pool 복사·최신 snapshot·배포 상태|기존2M pool을 분기 복사하고 학습 actor만 정확히 전환하는 안|전환 구현 전|
|PPO 추가 상한|첫 상세평가 지점 명목2.4M까지 제안. 자동 장기 연장 없음|학습 실행 전|
|PPO-only 대조 실험|BC의 독립 효과가 필요할 때 추가|예산 확정 시|

패스가 잠시 늘었다가 PPO에서 다시 사라지면 이를 실패/퇴행으로 보고한다. 보상·상대 분포·명령 중복의 추가 실험을 새로 계획하며, 이번 계획에 강제 패스나 보상 변경을 몰래 추가하지 않는다.

주간 잔여4% 이하 또는 치명적 오류 시 저장·중단한다. BC도 actor·optimizer·카운터·난수·데이터 진행 상태를 저장해야 한다. 그 외에도 데이터 누출, 출처 불일치, 원본 변경, 정책 덮어쓰기, 비유한값, 잘못된 PPO 경험 사용은 재개 전 해결 대상이다.
