# MS3-v3 R6 첫100k 실행 및 치명적 무결성 문제 중단

2026-09-25 사용자 지시: 새 optimizer·새 pool로 R6를 시작하고 치명적 문제가 없으면 최소600k까지 수행한다. 주간 잔여량4% 이하에서는 저장·중단한다. 이번 실행 상한600k로 준비했다.

## 결과

Run `MNG_MS3V3-20260925-r001`은 **100809 step에서 정상 저장·정지**했다. 이후100k 점검에서 치명적 다중 worker 기록 충돌을 확인해 `monitor-100k.json`에 **passed=false**를 기록했다.200k·400k·600k는 실행하지 않았으며 champion 승격도 없다. 주간 잔여량은 시작15%, 종료 확인13%로 사용량 기준에 도달하지 않았다.

승인 MS2 actor(step200120)의 가중치만 복사하고 step0·새 optimizer·새 pool로 시작했다. 초기 MS2 snapshot 하나만 pinned이며 외부 history/구 MS3-v2 400k는 사용하지 않았다.32환경, seed20260923, pool seed20260922, 기존 PPO 설정과 runtime을 유지했다.

## 재검증

기존 준비 manifest는 보존했다.97소스 중57동일,38개 줄바꿈만 다름(혼합 줄바꿈4개는 보존 snapshot의 원본SHA로 확인), 실행기는500k/600k 정지점 추가, 준비기는 전체 검토 및 maximum-steps 인자를 추가했다. 준비기 원래 byte 배열은 완전히 복원하지 않았고 새 준비물을 생성했다. 게임 소스·학습 adapter·optimizer 구현·YAML 하이퍼파라미터는 변경하지 않았다.

Python37/37,32환경 동시 barrier와512결정(학습0),새 launcher ValidateOnly를 통과한 뒤 실제 학습했다. 이전 Edit357/357·Play54통과와 D4 동결80경기 증거는 동일 runtime의 과거 결과를 재사용했다. 이 짧은 preflight는 장시간 공용 파일 충돌을 검출하지 못했다.

## 치명적 문제

- 26개 Player 로그에서 IOException54회. `spawns.jsonl`과 `common-rules.jsonl`을 여러 프로세스가 같은 경로에 File.AppendAllText한다.
- `MNG_V2Trace.cs:77`의 예외가 `MNG_MatchController.ResetRound():479`를 통해 전파된다. 해당 호출 뒤에 possession/carrier 초기화, Playing 상태 전환, GoalPause 해제가 있어 단순한 출력 누락으로 취급할 수 없다.
- worker6528은 초기 ResetMatch에서 예외가 나 `MNG_MSController.Start()`의 InitializeEvidence에 도달하지 못했다. v2 telemetry32개는 존재하지만 worker-start/episode 파일은31개다.
- `inspect_mng_v2_training.py`가 `Missing training workers`로 실패했다. 검사를 완화하거나 누락 기록을 채워 넣지 않았다.
- trainer의 표준 로그는 정상 종료했으나 Player 예외는 개별 `run_logs/Player-*.log`에서 확인됐다. 향후 정상성 감시는 이 로그들을 실시간으로 포함해야 한다.
