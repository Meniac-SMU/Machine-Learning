> 2026-09-21 사용자 확정 변경: 아래 최초 권장안의 16환경·100k/20k 조건은 [MS2 P0 proof 실행 계약](ms2-p0-proof-plan-20260921.md)으로 대체한다. 실제 proof는 32환경, 최대 500k, 100k마다 전체 300초 고정 평가, 무작위 대비 +0.20, 독립 평가 seed 재현을 사용한다. P0 범위와 P1 분리는 유지한다.

작성일: 2026-09-21

대상 Run: `MNG_MS2-20260920-r003`

결론: **MS2 100k 확장과 평가는 완료했다. PPO는 R0-Full을 상대로 전진·슛·회수 중심의 강한 정책을 실제로 학습했다. 다만 패스 판단은 거의 학습하지 않았고, 일부 Planner 로직은 감독의 전략 판단을 대신하고 있으므로 MS3 전에 보조 경계를 한 번 정리하는 것이 권장된다.**

## 1. 이번 작업의 범위와 판정

사용자 지시에 따라 다음 순서로 작업했다.

1. MS2 학습 상한을 aggregate `100,000` manager step으로 두고 16개 독립 Windows Player 환경에서 학습했다.
2. 약 20k 간격으로 checkpoint, trainer reward, 고정 R0-Full 평가를 보존했다.
3. 진전이 완전히 멈추면 중단하고, 회복·향상이 확인되면 100k까지 진행하는 기준을 적용했다.
4. 100k 완료 뒤에만 코드 보조가 감독 판단을 대신하는 범위를 감사했다.
5. 가장 큰 개입인 `막힌 전진 상황의 강제 패스 전환`을 끈 통제 평가를 20k·60k·100k checkpoint에 수행했다.

기존 완료 Run `MNG_MS2-20260920-r002`와 그 모델·로그는 덮어쓰지 않았다. 새 Run은 `r003`, seed `192002`, port `5920..5935`, R0-Full, CUDA, 16환경으로 별도 보존했다. 선택 MS1 `MNG_MS1-20260920-r007-step7443`의 정책 가중치에서 시작하되 optimizer는 새로 만들었다.

## 3. 가장 큰 코드 보조: 강제 패스 전환

### 3.1 발견한 동작

`MNG_ManagerAgent`는 `-mngMS1LearnPassChoice true`가 없으면 정책이 고른 명령을 그대로 적용하지 않는다.

- [MNG_ManagerAgent.cs](../../../../Assets/_Soccer/Manager/Runtime/MNG_ManagerAgent.cs) 88~91행: `m_LearnPassChoiceMode`는 명령행 인자로만 켜진다.
- 같은 파일 149~157행: 차단 상황에서 정책이 `PassBuild`를 직접 고르면 명령 선택 자체에 보상을 준다.
- 같은 파일 158~167행: 학습 모드가 아니면 `ApplyBlockedForwardPassPriority`로 정책 명령을 사후 교체한다.
- [MNG_Command.cs](../../../../Assets/_Soccer/Manager/Runtime/MNG_Command.cs) 93~106행: 전진이 막히고 패스 대상이 있으면 `PassBuild`와 `AttemptShot` 이외의 요청을 `PassBuild`로 바꾼다.
- [MNG_MS2_Train.ps1](../../../../Tools/MNG_MS2_Train.ps1) 72~77행과 [MNG_MS2_Evaluate.ps1](../../../../Tools/MNG_MS2_Evaluate.ps1)은 이 비활성화 인자를 전달하지 않는다.
- MS1의 `PassDecisionPolish`만 [MNG_MS1_Train.ps1](../../../../Tools/MNG_MS1_Train.ps1) 136~137행에서 해당 인자를 전달했다.

따라서 r003 학습과 기존 최종 평가에는 강제 전환이 켜져 있었다. 100k 최종 평가에서 정책이 직접 고른 PassBuild는 `3회`뿐인데 실제 적용 PassBuild는 `807회`였고, 그중 `804회`가 사후 교체였다. 완료 패스 34회가 발생했지만 다수는 PPO가 패스를 선택해서 만든 결과가 아니다.

이 구조는 인과 credit을 흐린다. PPO는 예를 들어 `Balanced`를 선택했는데 환경이 `PassBuild`를 실행하고 완료 패스 보상을 돌려줄 수 있다. 관측과 정책 action 사이의 결과가 어긋나므로 학습이 패스 선택을 배웠다고 해석할 수 없다.

## 4. PPO가 배운 것으로 볼 수 있는 전략

현재 증거로 가장 타당한 해석은 **패스를 거의 쓰지 않는 직접 전진·슛·회수 전략**이다.

1. 강제 패스가 없는 상태에서도 무작위보다 `+75%p` 높은 score rate를 기록했다.
2. 100k 정책은 2만 정책보다 동일 120초 진단에서 `+12.5%p` 높았다.
3. 300초 최종에서 정책은 무작위보다 유효 슛을 `55.8%`, 5m 전진을 `71.6%` 더 만들었다.
4. 기존 보조를 끄자 정책이 직접 선택한 `AdvanceCarry`와 `AttemptShot`이 실제로 실행되어, 유효 슛 `251 → 374`, 5m 전진 `654 → 1014`로 늘었다.
5. 같은 실행 코드와 유효명령 집합을 쓰는 무작위 감독은 같은 수준의 결과를 내지 못했다.

여기서 PPO가 배운 대상은 선수 한 명의 조향이나 킥 각도가 아니다. 관측된 선수·공·소유·점수·이전 명령 상태에 따라 `AdvanceCarry`, `AttemptShot`, `ActiveRecover`, `Balanced`, `ProtectBack` 중 어느 팀 명령을 언제 유지하거나 바꿀지를 배웠다. 이것은 저수준 기술을 코드 옵션으로 둔 계층형 강화학습으로 판단할 수 있다.

반대로 **패스 선택을 배웠다고 말할 수 없다.** 24,004번의 최종 정책 판단 중 직접 PassBuild는 3번뿐이고, 강제 전환을 끄면 완료 패스는 1번이다. 사용자가 MS2에서 패스를 핵심 gate로 두지 않았으므로 경기 성능 판정은 통과할 수 있지만, `막혔을 때 패스를 스스로 우선한다`는 목표는 아직 달성되지 않았다.

## 5. 추가로 발견한 전략 수준 코드 개입

선수 기술 보조 전체를 제거하는 것은 MS의 설계 목표와 맞지 않는다. 다만 아래 로직은 이동 실행을 넘어 감독의 전술 결정을 대신할 가능성이 높다.

### 5.1 명령과 무관한 2인 압박

[MNG_TeamPlanner.cs](../../../../Assets/_Soccer/Manager/Runtime/MNG_TeamPlanner.cs) 114~120행은 `RequiresDoublePressure`를 감독 명령과 별도로 계산한다. 같은 파일 754~763행에 따르면 상대 소유이면 항상 2인 압박이 켜지고, 중립 공도 자기 골문 위협이면 켜진다. `ProtectBack`을 선택해도 2인 압박이 발생할 수 있어 `ActiveRecover`, `Balanced`, `ProtectBack`의 차이를 줄인다.

### 5.2 명령과 무관한 공격 지원

같은 파일 121~123행과 779~793행은 상대 골문 근처에서 감독 명령과 무관하게 두 번째 공격 지원자를 고른다. 전진·패스·슛 명령의 전술 차이를 코드가 일부 미리 만든다.

### 5.3 자동 정체 슛과 골키퍼 자동 배급

같은 파일 124~150행, 273~307행은 공 정체 시 감독 명령과 무관하게 슈터를 선택하고, 350~376행은 골키퍼가 공을 잡으면 자동 패스 또는 슛을 선택한다. 특히 현재 133개 관측에는 공 위치·속도는 있지만 `BallStallRecoveryActive`와 정체 지속시간이 직접 들어 있지 않다. 숨겨진 상태에서 자동 슛만 제거하면 정책이 대응할 정보가 부족해진다.

### 5.4 자기 골문 위협 시 자동 미드필더 복귀

같은 파일 613~621행은 자기 골문 위협에서 미드필더를 자동 Cover로 바꾼다. 안전장치 가치가 있지만, 방어 명령 선택의 일부를 대체한다.

- 골키퍼의 물리적 홈 위치, 골문 차단, 공 접근 제한과 같은 안전 실행
- 공 소유자가 없거나 킥 준비가 안 된 상태에서 물리적으로 불가능한 명령을 막는 action mask

현재 정책의 action은 여섯 팀 명령뿐이다. 수신자 좌표, 선수별 조향, 킥 접촉까지 PPO가 직접 출력하게 바꾸면 Manager-Simple이 아니라 선수 제어 RL로 문제 자체가 달라진다. 저수준 기술을 코드로 안정화한 상태에서 고수준 판단을 PPO가 맡는 구조는 강화학습으로 유효하다.

## 7. 권장 수정안

### P0 — 다음 학습 전에 반드시 적용할 최소 수정

1. 신경망 감독의 기본 모드를 `정책 요청 명령 그대로 실행`으로 바꾼다. 역사적 이름인 `-mngMS1LearnPassChoice` 대신 `-mngPolicyAssistMode none|legacy`처럼 범위를 드러내는 옵션을 만들고, MS2/MS3는 `none`을 기본값으로 고정한다.
2. `ApplyBlockedForwardPassPriority`는 R0 규칙형이나 과거 호환 평가에서만 명시적으로 켠다. PPO 학습·평가에서는 사후 action 교체를 금지한다.
3. [MNG_RewardProfile.cs](../../../../Assets/_Soccer/Manager/Runtime/MNG_RewardProfile.cs) 28·44행의 `BlockedForwardPassDecision +0.01`을 proof 학습 profile에서 제거한다. 명령 선택 자체가 아니라 `CompletedPass`, `ValidShot`, `AdvancedFiveMeters`, 회수, 득실과 승패만 보상한다.
4. proof 평가에 `rawCommandCounts == effectiveCommandCounts`, `blockedPassOverrides == 0`, `explicitBlockedPassRewards == 0`을 필수 gate로 추가한다. 위반하면 승률과 관계없이 실패시킨다.
5. 기존 패스 완료의 물리 기준 `2.5m 이동 + 다른 동료의 0.15초 안정 소유`와 보상 `+0.06`, cap `+0.10`은 유지한다. 결과 사건 보상 자체에는 문제가 없다.

### P1 — 전략 Planner의 명령 종속성 강화

한 번에 모두 바꾸지 말고 아래 항목을 각각 분리해 A/B 평가한다.

1. 2인 압박은 `ActiveRecover`에서 2명, `Balanced`에서 1명, `ProtectBack`에서 0~1명과 후방 Cover처럼 명령별로 구분한다.
2. 상대 골문 근처 공격 지원자는 `AdvanceCarry`, `PassBuild`, `AttemptShot`에서만 켜고, `Balanced`와 `ProtectBack`에서는 각 명령의 기본 포메이션을 따른다.
3. 골키퍼 소유 시 `PassBuild`는 안전 배급, `AttemptShot`은 먼 클리어, 그 외 명령은 짧은 안전 보유/이동으로 연결한다. 물리적 시간 초과 안전 클리어는 별도 safety event로 기록한다.
4. 자동 정체 슛은 제거하되 두 선택지 중 하나를 먼저 택한다.
   - 관측 계약 v2에 `stallActive`와 정규화된 정체 시간을 추가해 PPO가 명령을 선택하게 한다.
   - 또는 학습 가능한 전략 행동을 만들지 않는 중립적인 공 재배치/reset으로 처리한다.
5. 자기 골문 위협의 자동 미드필더 Cover는 `ActiveRecover`, `Balanced`, `ProtectBack`에만 허용하고 공격 명령을 선택한 정책에는 그 선택의 위험도 남긴다.

## 8. 실제 RL 발전을 증명할 다음 실험

현재 100k 모델은 강제 패스 보조가 켜진 환경에서 학습했다. 보조를 끈 평가가 매우 강하다는 것은 의미 있는 증거지만, **보조 없는 학습 그 자체**를 아직 증명한 것은 아니다. 다음 한 번의 짧은 proof Run이 필요하다.

1. P0만 적용한다. P1은 섞지 않는다.
2. 동일한 MS1 `step7443` 정책 가중치에서 새 optimizer로 시작한다. r003 PT를 이어 쓰면 보조 환경에서 배운 이력이 섞이므로 깨끗한 증명이 되지 않는다.
3. 16환경, R0-Full, 동일 reward, 최대 100k를 유지한다.
4. 20k마다 no-assist 고정 평가를 수행한다. `raw/effective mismatch 0`과 직접 명령 보상 0을 먼저 검사한다.
5. 2만·6만·10만 checkpoint의 독립 seed 평가가 무작위보다 계속 높고, 최종 양 진영 score rate·득실·행동 사건을 통과하면 no-assist PPO로 승인한다.
6. 패스는 이번 MS2의 필수 승격 조건으로 다시 높이지 않는다. 대신 `직접 PassBuild 선택률`과 `완료 패스`를 별도 관찰 지표로 남겨 pass-free 정책임을 투명하게 표시한다.
7. P0 proof가 통과한 뒤 P1을 한 항목씩 적용하고, 성능과 명령별 행동 차이가 실제로 커지는지 본다. 여러 전략 보조를 동시에 제거하면 실패 원인을 분리할 수 없다.

권장 승인 기준은 다음과 같다.

- 양 진영 각각 score rate `0.40` 이상
- 합산 score rate `0.50` 이상
- 득점 `>=` 실점
- 동일 조건 무작위보다 `+0.20` 이상
- `blockedPassOverrides == 0`
- `raw == effective` 전 명령 일치
- 직접 명령 선택 보상 `0`
- 한 명령 고정률이 지나치게 높지 않고 Advance/Shot/Recover가 실제 경기 사건으로 이어짐
- 최소 2개 학습 seed 또는 선택 모델의 추가 독립 평가 seed로 재현

## 9. 최종 판단과 한계

현재 게임은 강화학습의 껍데기만 씌운 순수 규칙형 게임이라고 판단하지 않는다. 같은 선수 기술·Planner·물리·action mask를 받은 무작위 감독과 PPO 감독의 격차가 매우 크고, 보조를 끈 checkpoint 추이도 학습량과 함께 상승했다. 특히 강제 패스를 제거한 100k 정책의 `0.9125 대 0.1625`와 실제 슛·전진 격차는 PPO의 고수준 판단이 경기 결과를 바꿨다는 강한 증거다.

동시에 현재 구조를 완전한 감독 판단 학습이라고 부르기에는 전략 수준 Planner 개입이 남아 있다. PPO가 분명히 배운 부분은 직접 전진·슛·회수의 선택과 전환이며, 패스 판단과 일부 압박·지원·정체 대응은 코드가 대신하거나 숨겨진 상태로 처리했다.

따라서 MS2 경기 성능 목표는 완료로 유지하되, MS3 self-play 전에 P0의 no-assist proof Run을 한 번 수행하는 것이 가장 빠르고 신뢰도 높은 경로다. P1은 그 뒤에 단계적으로 적용한다. 이번 작업에서는 감사와 수정안만 작성했으며 런타임 행동 코드는 변경하지 않았고 MS3도 시작하지 않았다.
