## 사용자 결정과 이번 작업의 경계

- 사용자가 현재 R0를 완료로 판정했다. 승인 대상은 현재 Planner v9·킥 세기 증가가 반영된 R0다. 과거의 육안 승인 대기 문구는 당시 기록이다.
- 기존 M0/M1/M2/M3 이후 순차 커리큘럼을 계속 진행하지 않고 **MS0 → MS1 → MS2 → MS3**를 신설한다. 기존 코드·씬·모델·Run·실패 증거는 보존한다.
- MS0는 2026-09-19 구현·빌드·병렬·resume·self-play 연결을 완료했다. 정확한 증거와 예산 편차는 [MS0 완료 보고서](ms0-completion-20260919.md)를 따른다. MS1 이후의 코드·학습은 별도 후속 작업이다.
- MS1과 MS2를 거쳐 MS3도 2026-09-21 완료했다. 공식 MS3 Run `MNG_MS3-20260921-r002`는 32환경 PPO self-play를 `300,028` step까지 실행했고 300k 완료 gate를 통과했다. 선택 정책과 고정평가·행동 무결성·시연 빌드는 [MS3 완료 보고서](ms3-completion-20260921.md)를 따른다.
- 아래 수치는 빠른 완성을 위한 **설계 초기값**이며 달성 실적이나 사용자 지정 수치가 아니다. 개발 세션은 이 계획의 범위 내에서 구현하고, 계약 또는 예산을 바꾸면 변경 이유·전후 값을 먼저 기록한다. 원칙적으로 실패 결과를 본 뒤 합격선을 낮추지 않는다. 다만 2026-09-20 사용자가 패스만 남은 경우 통과시킬 의향과 성공 기준 소폭 완화를 명시했으므로, MS1 v8은 새 holdout seed를 사용해 실제 패스 최소 `2/20`과 무작위 baseline 비열등을 요구한다. 공격·수비 gate와 물리적 완료 판정은 완화하지 않았다.

## 바꾸지 않을 큰 틀

- 팀당 감독 Agent 하나, PPO 하나, 숫자 관측 133개, 이산 branch 하나에 명령 6개를 유지한다. `AdvanceCarry / PassBuild / AttemptShot / ActiveRecover / Balanced / ProtectBack`의 의미를 유지한다.
- 선수는 새로 학습시키지 않는다. 이동·회전·공 추격·드리블·패스 대상/수신·슛 조준·킥 접촉·골키퍼·간격·정체 해소는 현재 공통 코드가 수행한다. PPO는 상황에 따른 명령 선택과 전환 시점을 학습한다.
- 4v4, 경기장·외형·UI·물리·현재 킥 세기·시작/킥오프 스폰 변화는 그대로 재사용한다. 기존 HUMAN 계약도 보존하되 MS 학습/고정평가에서는 양 팀 모두 AI로 두어 변수를 줄인다.
- 규칙형 상대는 Core Fallback이 아니라 **현재 `MNG_RuleBasedManager` R0**다. 기존 `M3-FallbackMatch`를 이름만 바꾸어 MS로 쓰지 않는다.
- 첫 MS 정책은 fresh PPO다. 현재 물리·관측 정규화 이전의 M1 r001~r003을 resume/initialize하지 않는다. MS1→MS2→MS3는 호환 계약의 검증된 PT를 이어받는다.
- 신규 전용 파일은 `MNG_MS*` 접두사로 만들고, 공통 Planner/Executor/관측/마스크/보상 판정을 복제하지 않는다.

## MS1: 두 상황군을 동시에 가르친다

- 에피소드 시작 시 공격 50%, 수비/전환 50%를 추첨한다. 각 군의 소유 선수·좌우 측면·공 위치를 정해진 안전 범위 안에서 바꾼다. 공격/수비는 stage가 아니라 reset 분포다.
- 공격: 자기 팀 소유로 시작하며, 전진 공간/패스 통로/슈팅 가능 위치를 고르게 섞는다. 기존 M1 시나리오 중 유효한 reset 코드를 재사용할 수 있으나 기존 패스 횟수 gate와 보상은 자동 상속하지 않는다.
- 수비/전환: 절반은 상대 소유, 절반은 중립 공으로 시작한다. 회수·균형·후방 보호의 차이를 경험한다. R0도 실제로 공을 추격하고 슛할 수 있어야 한다.
- 30초 또는 첫 득점으로 종료한다. 30초 도달은 학습용 구간 절단이므로 bootstrap 가능한 interruption을 사용하고, 단순 시간 종료를 승리로 보상하지 않는다. 득점은 실제 goal 사건으로 처리한다.
- 첫 강도는 R0 0.35. 너무 어려운 경우에만 0.20을 최대 첫 20k step까지 사용한다. MS1 통과 평가는 항상 0.35에서 시행한다.
- MS1은 완벽한 축구를 요구하지 않는다. 여섯 명령을 같은 비율로 사용하는 조건이나 무수비 패스 99% 재학습은 없다. 단, 공격·수비 양쪽 학습 근거 없이 통과시키지 않는다.
- 2026-09-20 사용자 결정에 따라 MS1 학습은 Windows Player 독립 환경 16개를 `--num-envs 16`으로 고정한다. aggregate 100k 상한은 worker 수만큼 늘리지 않는다. 16개가 불안정하면 자동 축소하지 않고 저장·중단한다.
- 2026-09-20 MS1은 선택 후보 `MNG_MS1-20260920-r007-step7443`가 `MNG-MS1-v8` 고정 평가를 통과해 완료되었다. 실제 결과와 선택 근거는 [MS1 완료 보고서](ms1-completion-20260920.md)를 따른다. MS2는 이 번호가 붙은 PT에서 시작한다.

## R0 약화와 기준 상대 보존

| 강도 프로필 | 상대 AI 이동 속도 배율 | 상대 감독 판단 간격 | 사용 |
| --- | ---: | ---: | --- |
| R0-Easy | 0.35 | 1.5초 | MS1 기본 |
| R0-Rescue | 0.20 | 2.0초 | MS1 첫 20k 내 임시 구조 구간 |
| R0-Medium | 0.60 | 1.0초 | MS2 첫 최대 20k, 필요 시에만 |

- 이 프로필과 적용 경로는 MS0에서 구현했다. Profile이 상대 Rule 감독의 판단 간격과 상대 선수의 모든 공통 이동 경로 배율에 적용되며, Full은 현재 R0의 `1.00×/0.5초`와 같다.
- MS 전용 인스턴스 설정으로 상대만 약화하고 R0 원본 Scene/Prefab/상수의 기본값을 바꾸지 않는다. MS2 이후 Full은 프로필 미적용 R0와 기능적으로 같아야 한다.
- 속도 제한은 상대 AI의 모든 이동 경로(일반 이동·추격·간격 양보·정체/경계 탈출 포함)에 일관되게 적용한다. 공·킥 파워·질량·콜라이더·물리 시간·소유 판정을 약화 수단으로 쓰지 않는다.
- 고정평가 manifest에 프로필과 실제 적용값을 기록한다. 낮은 강도에서의 성과를 정상 R0 성과로 표시하지 않는다.

- 두 연속 checkpoint 평가에서 해당 단계 주지표가 개선되지 않으면 정상 저장 후 원인을 분석한다. 같은 실패 2회면 미세 보상 수정·새 Run 반복 대신 관측/마스크/명령 영향/기술 실행/상대/보상/평가를 점검한다.

## 제외하는 작업

선수별 RL, 기존 L 커리큘럼 재개, 이전 M gate 재수행, 행동/관측 대규모 재설계, 모방학습 데이터셋, 전술별 다중 모델, Human 포함 학습, 별도 리그, 네트워크/배포/UI 재설계는 MS 필수 범위가 아니다. H키 기존 기능은 변경 영향이 있는 경우만 회귀 확인하고 최종 시연에서 보존 여부를 확인한다.

## 기술 참고

병렬 실행은 하나의 trainer가 여러 Unity executable을 `--num-envs`로 실행하는 구성을 쓴다. [Unity 공식 병렬 학습 문서](https://unity-technologies.github.io/ml-agents/Training-ML-Agents/)를 참고하고 실제 인자는 설치된 trainer로 검증한다.

Self-play는 같은 BehaviorName과 서로 다른 Team ID를 가진 양 팀 감독을 사용한다. [Unity 공식 Agent 문서](https://unity-technologies.github.io/ml-agents/Learning-Environment-Design-Agents/)와 [self-play 설정](https://unity-technologies.github.io/ml-agents/Training-Configuration-File/)을 참고한다. 구체 초기값과 호환성 확인은 인계 문서를 따른다.
