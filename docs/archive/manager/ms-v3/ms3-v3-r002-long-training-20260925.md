## 658k 진행 기록 충돌 수정

658256 step에서 `progress.tmp -> progress.json`의 Windows 접근 거부로 trainer가 종료됐다. 종료 처리에서 checkpoint·optimizer·pool·ONNX가 저장됐으며 유한값·step 일치·Player32개 예외0을 확인했다. optimizer7314 updates, 진영327692/330564였다. 실패 구간 `to-700000`과 run_logs는 보존했다.

진행 상태 기록의 rename에 짧은 bounded retry를 추가하고, 읽기 잠금이 계속되면 임시 상태 파일을 남기고 다음 갱신에서 다시 시도하도록 했다. 기타 IO 오류와 Player 오류 중단 규칙은 유지한다. 실제 Windows 읽기 잠금·일시 충돌 회복·기타 IO 오류 전파의3개 테스트를 통과했다. 변경된 entry는 별도 hash 검증 repair gate 없이는 재개되지 않도록 했다. 새 gate를 통한 ValidateOnly 성공과 gate 생략 시 거부도 확인했다.

`progress-repair-gate.json`과 `extension-gate-1m-progress-fix.json`이 원본 manifest 및 변경 전후 entry/launcher를 연결한다. PPO adapter·runtime·optimizer·pool은 유지하고 `to-700000-resume-01`에서701708 step까지 정상 저장했다. 기존 실패 원본이나 최초 manifest를 덮어쓰지 않았다.
