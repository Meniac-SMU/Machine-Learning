# MS3-v3 r002 1.6M 평가 및 포트 충돌 복구

2026-09-25. 사용자 승인 목표는2M,정규 평가는400k 간격이다. 현재1,600,333 step 저장·평가를 완료했으며2M은 아직 완료하지 않았다.

## 완료 범위

- 같은 r002의1,000,049 checkpoint에서 optimizer·상대 풀을 이어받아1,600,333까지 학습했다.
- 1.1M·1.2M·1.3M·1.4M·1.5M·1.6M마다 저장·상태·행동 기록을 검사했다.32환경,원본 runtime·보상·PPO 설정을 유지했다.
- 1.2M과1.6M에 각각320경기,총640경기를 평가했다. 각 상대20개 seed×양 진영=40경기,경기당300초이며 무작위 상대는 제외했다.
- R6 완료 상태와 champion400719를 유지한다. 최신 checkpoint를 자동 승격하지 않았다.

## 저장·무결성

최종 양 진영 학습 전이는Red815606/Navy784727,optimizer update17820이다. entropy0.336446,Approx KL0.000630,policy loss0.046556,value loss0.088944로 모두 유한값이다.32환경 기록·명령/타격 연결·checkpoint/pool 복원 검사를 통과했다. 완료 학습 구간과 평가 Player 오류는0건이며 평가 전후 모델·optimizer·pool SHA 일치를 확인했다.

## 1.7M 시작 실패와 재개 조건

1.7M 구간 재개 도중 worker7의 통신 포트6507에서WinError10013이 발생했다. 당시 GoogleDriveFS(pid39508)의HTTPS 연결이 해당 로컬 포트를CLOSE_WAIT 상태로 사용하고 있었다. Windows TCP 동적 포트 범위는1024~15000이었다.

실패 시도는31개 worker-start 및 초기 spawn 기록만 남겼고 학습 결정·완료 학습 경기는0이다.1.6M checkpoint·optimizer·pool·번호별PT·ONNX 해시는 전부 그대로다. 실패 시도를 `startup-failed-to-1700000`으로 보존했고 실제 학습 구간 검사와 구분했다. 다른 프로그램을 종료하거나 통신 설정을 변경하지 않았다.

현행 `MNG_MSController`는 통신 포트 번호를 worker identity 및 spawnSeedOffset으로 사용한다. 따라서 포트 변경은 초기 배치 난수도 바꾼다. 사용자에게 다른 포트로 재개할지,기존 포트 해제를 기다릴지 선택을 요청했으나,답변 전 기존 포트가 해제됐다. 원래32개 포트의 동시 bind 검사를 통과한 뒤 원래 설정으로 재개했으며 앞선 선택은 불필요해졌다. 다른 프로그램 종료·포트·배치 난수·runtime·PPO 변경은 없다.
