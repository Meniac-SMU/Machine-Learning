﻿# MNG 커리큘럼·보상·훈련 계약

> 2026-09-19 이후 감독 RL 커리큘럼·예산·승급 기준은 [MS 계획](../ms-v1/ms-plan.md)과 [MS 평가·보상 계약](../ms-v1/ms-validation.md)이 우선한다. 아래 기존 M 단계의 gate/예산/일정은 MS에 자동 상속하지 않는다. 기존 Profile/보상 코드가 이번 문서 작업으로 변경된 것은 아니다.

모든 값은 실행 전 설계 초기값이다. 기존 선수 커리큘럼과 별개이며, 실제 평가 전에는 통과로 기록하지 않는다.

## 1. 기본 원칙

- M0는 기술 테스트이며 강화학습 단계가 아니다. 이동·드리블 성공률을 신경망 성능으로 기록하지 않는다.
- R0는 규칙형 감독 기준선이며 강화학습·보상·Trainer·ONNX를 전혀 사용하지 않는다. PPO와 같은6명령·Planner·기술층으로 판단 계층만 비교한다.
- M1부터 감독의 선택만 PPO로 학습한다. 선수의 공 탐색·접근·조준·수신·역할별 위치는 코드가 안정화하고, PPO는 관측133/행동[6]/결정0.5초에서 전술 선택과 전환을 학습한다.
- 경기장 축소는 금지한다. 시작 위치·소유 상황·상대 반응·episode 길이만 조절한다.
- 단계별 Scene은 공통 Prefab과 Catalog 설정을 사용한다. 진행 중 난이도 변경이나 순간이동은 하지 않는다.
- 새 단계는 PT 가중치를 초기값으로 쓰는 새 Run이다. 동일 Run 재개는 resume, 단계 초기화는 initialize-from/init_path로 구분한다. ONNX로 이어 학습하지 않는다.
- M1/M2에 수일 정체하면 안 된다.25k/50k/100k 이후20k~50k 간격의 checkpoint에서 고정평가와 명령·mask·실제 사건 분포를 함께 본다. 두 연속 평가에서 주요 성능이3%p 이상 오르지 않고 행동 다양성/실제 사건도 개선되지 않으면 정상 저장 후 조기 중단한다. 같은 gate의 구조적 실패가2회면 미세 r증가를 멈추고 기술·관측·mask·보상·상대·평가 전체를 점검한다.

- 연결·파서·빌드 smoke만1k 안팎의 짧은 Run을 허용한다. 중요 정책은 진전이 계속되는 경우100k 이상 aggregate manager decision을 거쳐100k와 최종 checkpoint를 각각 평가한다. 반대로 위 정체 조건이 확인되면100k 숫자를 채우기 위해 무의미하게 연장하지 않는다.
- 최대 step 또는 안전 wall limit에 도달하면 정상 저장·종료한다. 상한은 완료시간 예측이 아니다.
- 단계당 최대2회 보정 Run. 이유·단일 변경·비교표가 필요하다. 예산 종료 자체는 승급이 아니다.
- scoreRate=(승리+0.5×무승부)/경기수. 무승부만으로 통과하지 않도록 무득점 비율도 함께 평가한다.
- M1/M2는 득점·실점이 실제 terminal이며, 회수 성공으로 종료하려면 그 의미를 Catalog에 고정한다. M2 기본은 회수 후에도20초까지 진행해 실점을 측정한다.
- 예정된20/60초 수집 제한은 interrupted로 처리하고 별도 timeout 벌점을 주지 않는다. 300초 경기 종료는 승패가 정해지는 terminal이다. 이 둘을 혼동하지 않는다.
- M3 이후 득점은 episode 종료가 아니라3초 GoalPause다. 경기 종료에서 양 감독을 함께 끝내고 reset한다.

### Self-play 보상의 대칭성

- 득실점/승패는 직접 한 번 ±1/±0.5. 두 팀 ledger를 빼며 중복 지급하지 않는다.
- shaping은 각 팀 사건의 차이로 계산: Red=ownShaping-opponentShaping, Navy=-Red. 최종 차이에 공통 rolling 절댓값 cap을 적용해 정확한 대칭 유지.
- 양 팀의 명목 사건 원장과 최종 지급 원장을 구분한다. self-play 전환 시 보상 분포가 달라지므로 새 Run과 고정 상대 재평가 필요.
- 전술 self-play도 같은 Run 안에서 양 팀에 동일 profile을 적용한다.
- Human이 만든 팀 사건도 보상에 포함하되 Human/AI 기여를 따로 기록한다.

| keep_checkpoints |16, 평가 채택 파일 별도 보존|
| threaded |false|

smoke만 buffer256/batch64를 사용하고, 실제 학습은 위 값으로 새 Run을 만든다. 현 설치 trainer에서 YAML 키와 통신을 검증한다. 임의 대형망/CNN/RNN 추가보다 관측·실행을 먼저 진단한다.

Self-play 초기값: save_steps10000, swap_steps2000, team_change20000, window10, play_against_latest_model_ratio0.5, initial_elo1200. 감독 경험 수 기준이며 선수 frame 수와 혼동하지 않는다. 실제 상대 교체 로그로 설정 효과를 확인한다.

- 1환경 통신→4환경 성능→8환경 기본. RAM/처리량을 보고16까지 검토. 과거32worker 설정을 복사하지 않는다.
- time_scale20 시험 시작, 경기 논리는 simulated time, 운영 timeout은 wall time.
- 훈련 렌더/UI 비활성 가능, Geometry/충돌/제어는 시연과 동일.
- resume는 optimizer/step 보존. phase 초기화는 새 step·기존 가중치. optimizer 초기화의 실제 지원 동작을 loader로 확인한다.

## 5. HUMAN 준비 학습

스크립트 대역은 Human 입력 경로만 사용하며 감독의 명령을 읽지 않는다. 대역의 미래 목표/seed는 관측에 넣지 않는다.
M4 초기 episode는 전원AI50%/Human포함50%, 훈련 진영을 대칭 배치한다. 도중 전환0~2회, 소유 중·GoalPause 등도 포함한다.
대역은 전진 운반/정지/후퇴/급회전/패스 선호/슛 선호를 섞고 반응 지연·seed를 변화시킨다. 평가에는 새로운 seed와 실제 사용자 입력을 포함한다.
M5/M6는 Human 혼합 상황20%부터 검토하며 순수AI self-play 지표는 별도 기록한다. 모방된 사람의 분포가 실제 사람 일반화를 증명하지 않는다.
