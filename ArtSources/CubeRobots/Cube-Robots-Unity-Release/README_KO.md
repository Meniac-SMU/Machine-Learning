# 확정 큐브 로봇 4종 — Unity용

## 포함된 확정본

| 파일 | 원본 |
|---|---|
| RedRobot.fbx | 빨강 로봇 v03 |
| NavyRobot.fbx | 밝기·채도를 올린 네이비 로봇 v02 |
| PinkGoalkeeper.fbx | 빨강 로봇의 눈·바퀴 캡·포인트 색상을 적용한 분홍 골키퍼 v02 |
| SkyGoalkeeper.fbx | 하늘색 골키퍼 v01 |

각 모델: 메시 1개, 재질 슬롯 2개, 삼각형 5,768개. 모든 부품 고정. 리깅·애니메이션·스튜디오 조명·카메라·참고 이미지 제외.

## Unity 적용

1. 이 배포본의 `Assets/CubeRobots` 폴더를 Unity 프로젝트의 `Assets` 아래로 복사한다.
2. Unity가 FBX와 텍스처를 임포트하고 편집기 스크립트 컴파일을 마칠 때까지 기다린다.
3. 메뉴 **Tools > Cube Robots > Create Materials and Prefabs**를 실행한다.
4. 생성된 `Assets/CubeRobots/Prefabs`의 네 프리팹을 사용한다.

제공 도구는 Built-in 또는 URP를 감지하여 재질과 프리팹을 생성한다. HDRP·커스텀 파이프라인에서는 수동 재질 구성이 필요하다. 도구는 씬을 수정하지 않으며 물리·이동·AI 컴포넌트를 추가하지 않는다. 이 파일들은 일반 FBX 자산이므로 도구 없이도 수동 임포트할 수 있다.

도구를 다시 실행하면 이 폴더 안의 생성 재질과 프리팹을 갱신한다. 개별 수정은 복제한 프리팹/재질에서 진행하는 것을 권장한다.

## 크기와 방향

- 원본 Blender 단위 설정을 적용하여 **몸체 정육면체 한 변 = 1m**로 추출했다.
- 전체 높이 약 1.04m, 바퀴를 포함한 폭 약 1.352m.
- 바닥 기준 피벗: 몸체 중심 바로 아래, 원점. 바퀴와 킥 플레이트 하단이 지면 높이 0에 닿는다.
- Unity 목표 축: +Y 위, +Z 전방. FBX의 축 정보를 사용하도록 Bake Axis Conversion을 설정한다.
- 프리팹의 전체 Scale로 게임에 맞는 크기를 조정할 수 있다.
- 캐릭터 전체가 이동하므로 Static으로 표시하지 않는다.

## 재질과 텍스처

- 첫 번째 슬롯: 몸체·바퀴·포인트 부품의 팔레트 재질.
- 두 번째 슬롯: 눈. HDR 색상의 Unlit 재질로 주변을 비추는 광원 없이 밝게 보인다. Bloom의 번짐은 프로젝트의 후처리 설정에 따른다.
- `*_BaseColor.png`: sRGB, 팔레트 색상. 일반 로봇 128×16, 골키퍼 256×16.
- `*_MetallicSmoothness.png`: Linear/Non-Color. R=Metallic, A=Smoothness. Blender의 거칠기에서 `Smoothness=1-Roughness`로 변환했다.
- 팔레트는 Point 필터, Mipmap 끔, 압축 없음으로 설정한다. 편집기 도구가 자동 적용한다.
- Blender 전용 재질 노드, 카메라 전용 발광 노드와 조명은 FBX만으로 동일하게 재현되지 않는다. 동봉 도구가 Unity용 재질을 별도로 구성하며, 최종 색감은 프로젝트의 조명·색 공간·톤 매핑에 따라 달라진다.
- 재질은 인스턴싱을 허용하지만 실제 배칭 방식과 드로 콜 수는 프로젝트 설정 및 셰이더에 따라 달라진다.

## 검증 상태

4개 FBX 모두 Blender에서 재임포트하여 메시 수, 재질 슬롯, UV, 삼각형 수, 크기 및 바닥 높이를 검증했다. 원본 .blend 파일 SHA-256을 비교해 원본이 변경되지 않았음을 확인했다. 세부 결과는 `export-validation.json`에 있다.

**실제 Unity 프로젝트에서 편집기 도구를 실행하거나 프리팹 외형·성능을 측정한 상태는 아니다.** 편집기 도구는 실행 시 메시/서브메시 수, 삼각형 수와 임포트 높이를 검사하고 불일치 시 오류를 표시한다. Collider, Rigidbody, 이동 스크립트는 게임의 제어·충돌 방식에 맞게 추가해야 한다.
